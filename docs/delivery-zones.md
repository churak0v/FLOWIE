# Зоны доставки FLOWIE

Экран администратора: `/delivery`, также **Профиль → Доставка**. Доступ только роли `admin`.

1. «Добавить зону»: название, граница на карте Яндекса, стоимость в целых рублях, условия/сроки и порядок применения.
2. Обведите границу минимум тремя точками без пересечений, завершите рисование. До 200 точек, без внутренних отверстий.
3. Сохраните черновик либо включите зону. Без ключа Яндекс JS API можно сохранять черновики без геометрии и тарифа; геометрия становится доступна после подключения.
4. При пересечении зон действует меньший номер порядка; при равенстве — ранее созданная зона. Граница включается в зону. Ноль рублей — явно бесплатная доставка.
5. Явный режим расчёта: **Единый тариф** (по умолчанию, `DELIVERY_TARIFF_RUB`) либо **По зонам**. Создание черновиков и активация отдельных зон не переключают режим. После подготовки включённых зон выберите **По зонам**. В этом режиме fallback к единому тарифу запрещён: все зоны выключены/удалены или адрес вне зон — авторасчёт недоступен. Для возврата к единому тарифу нужно явно выбрать его в настройках.

Автоматический расчёт требует включённого `YANDEX_MAPS_ENABLED` и ключа Геокодера; сама карта — JS-ключа. Фронтенд сообщает об отсутствии подключения, но не подменяет карту вымышленной. Настройка ключей: `docs/yandex-delivery.md`.

`POST /api/delivery/estimate` и создание заказа рассчитывают стоимость по адресной строке через серверный геокодер. Принимается только точный результат уровня дома (`kind=house`, `precision=exact`). Клиентские координаты не определяют зону/цену. Квартира, подъезд, этаж и домофон после соответствующих маркеров обрезаются перед геокодированием. Вне зон — `DELIVERY_OUTSIDE_ZONES`; нет точного дома — `DELIVERY_ADDRESS_NOT_PRECISE`. Расчёт использует действующие зоны при запросе; цена уже созданного заказа сохраняется. Идемпотентный повтор возвращает ранее созданный заказ без повторного геокодирования.

Неизвестный адрес получателя остаётся прежним сценарием: основная оплата только товаров, доставка отдельным счётом после уточнения. Админ вправе согласовать индивидуальную доставку вручную. Условия зоны передаются в ответе estimate. Расписание магазина настраивается отдельно в **Профиль → Режим работы**.

REST: `GET/POST /api/admin/delivery-zones`, `PUT /api/admin/delivery-zones/mode`, `PUT/DELETE /api/admin/delivery-zones/:id`. До 100 зон; сервер проверяет имена, целые суммы, координаты, пересечения и допустимость активации. Сохранения и удаления пишутся в audit log. Миграция `20261118200000_add_delivery_zones`.

Внешний Яндекс без ключей не вызывался. Тесты проверяют геометрию/границы/пересечения, выбор зоны, отсутствие fallback вне зоны, запрет подмены цены клиентскими координатами и повтор заказа при недоступном провайдере. JS-редактор использует официальный API: https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/examples/cases/polygonEditor . Реальное рисование и точность адресов требуют проверки после подключения ключей.
