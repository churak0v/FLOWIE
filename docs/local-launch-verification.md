# FLOWIE: локальная проверка запуска, 18 ноября 2026

Это проверка локального development-стенда, не production-релиз и не настоящий платёж.

## Стенд

- Магазин: http://127.0.0.1:6212 ; Vite preview: http://127.0.0.1:6214 . Оба используют обновлённый API 6211.
- Админка: http://127.0.0.1:6213 ; настройки зон: `/delivery`, также Профиль → Доставка.
- Docker project `flowie`, локальный файл `.env.local-qa` (исключён из git, mode 0600). API/web/admin привязаны к loopback. Dev-admin включён только для локальной проверки. Банк, SMS, Яндекс и OpenAI отключены; токены ботов пустые, автоисполнение выключено.
- Перед обновлением сохранены БД и uploads в `/tmp/flowie-pre-refresh-20261118/`. Перед миграцией зон — дополнительный `before-zones.dump`. Это временные локальные копии, не постоянный production backup.
- Применены все 17 миграций, включая phone sessions, analytics, delivery invoices, embeddings, DeliveryZone и DeliverySettings. Каталог сохранён.
- Docker ограничен примерно 2 ГБ общей памяти: стандартная сборка admin и последующая Prisma generate получили exit 137. Для локального стенда интерфейсы собраны на хосте, Prisma Client сгенерирован на хосте с Linux ARM64 target, готовые артефакты упакованы в образы. Временный packaging context: `/tmp/flowie-local-package/`. Production-сборку необходимо повторить на подходящем builder; эти образы не публиковались.

## Найдено и исправлено

1. Общий nginx конфиг направлял `/` админки в SEO-витрину. Теперь у локальной админки отдельный `nginx/admin.conf`.
2. `VITE_DISABLE_TELEGRAM_BOOTSTRAP` блокировал и гостевую cookie-сессию. Теперь отключается только Telegram, обычный магазин создаёт гостевую сессию.
3. Админ-кэш отдавал прежний статус после подтверждения/обработки заказа. Успешная запись инвалидирует кэш; запущенное до записи чтение не заполняет его устаревшими данными.

## Проверено на работающем API и БД

- Через мобильный браузер: корзина → оформление гостем → уточнение адреса и времени у получателя → заказ №2 → перезагрузка с сохранением доступа → админка → ручная тестовая отметка основной оплаты → принятие → уточнение доставки с явным нулевым тарифом → загрузка фото через штатное кадрирование → передача в доставку → завершение. Покупательский API вернул `DELIVERED`, доставка `WAIVED`. Это не банковская оплата и не фактическая доставка.
- `FLOWIE_LOCAL_QA=true node scripts/qa/local-order-smoke.mjs`: заказы №3 и №4 созданы и отменены. Проверены cookie, серверная цена, повтор заказа без дубля, запрет доступа другому гостю, работа админа, отдельный счёт 700 ₽, повтор счёта без дубля, запрет отправки при неоплаченной доставке, отмена счёта с заказом, отзыв сессии при выходе. Тест не вызывает банк, SMS или ботов.
- CRUD зон на настоящей БД: сохранение и изменение черновика, сохранение режима flat, запрет включения неполной зоны и режима zones без активных зон. Проверочный черновик удалён; реальные границы/тарифы не выдумывались.
- Через UI `/delivery`: создание черновика с тарифом, перезагрузка, повторное открытие сохранённых данных и удаление прошли. На ширине 390 px горизонтального переполнения нет. Раздел открыт пользователю во встроенном браузере. Сохранённых тестовых зон не осталось.
- SEO: `/`, `/catalog`, `/product/55` — HTTP 200, публичный HTML и JSON-LD; несуществующий товар — HTTP 404/noindex; `/account` — noindex; robots и sitemap — HTTP 200.
- Админ-отчёт `/analytics` открывается и читает события/заказы из БД. Локальные тестовые оплаты попадают в локальную статистику и не являются выручкой магазина.
- 98 серверных тестов прошли, 3 integration-теста пропущены при обычном запуске без отдельной TEST_DATABASE_URL; 14 frontend unit-тестов прошли. Сборки витрины/админки, целевой ESLint и nginx syntax checks прошли.
